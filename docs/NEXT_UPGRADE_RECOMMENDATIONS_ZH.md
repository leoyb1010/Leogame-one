# 《Leo的地牢围攻》下一轮升级建议

## 结论

下一轮不应先扩玩法，而应先完成“高清视觉资产接入 + Apple 交互适配 + 产品发布基础”。当前模糊感主要来自三类源头：800×450 的章节插画、低分辨率像素 UI 图集、仍沿用原作的图标和视觉语言。单纯全局放大图片会让角色动画和格子边缘更糊，还会显著增加 iPhone/iPad 显存占用。

## P0：高清品牌素材接入

1. 接入 1024×1024 狮首 App Icon，并生成 iOS 全套尺寸和 macOS `.icns`。
2. 接入横竖两套标题背景及透明标题徽记，替换当前动态文字临时方案。
3. 将 11 张英雄/章节图统一升级为 1600×900 游戏资源，原始 2560×1440 文件保存在 `artwork/inbox/`。
4. 增加素材处理脚本：统一色彩空间、尺寸、JPEG 品质、PNG alpha 检查和体积预算。

验收目标：iPhone 3×、iPad 2×、5K Mac 截图中不出现插画插值模糊；单张运行时纹理控制在约 6 MB 以内。

## P1：Apple UI 与可读性

1. 建立 iPhone SE、常规刘海屏、Dynamic Island、iPad 11/13 英寸的竖横屏截图回归矩阵。
2. 把菜单面板、按钮和对话框改为高清 9-slice 组件；角色、地砖、物品 sprite 继续保持像素画，不做普通 AI 放大。
3. 为中文重新校准字号、行距、按钮最小触控面积，并检查长文本窗口的滚动和截断。
4. 增加安全区自动化检查，防止顶部状态栏和底部工具栏再次贴到圆角或 Home Indicator。

## P2：产品与发布基础

1. 创建 Leo 自有 GitHub 仓库，把 `upstream` 继续保留为只拉取的原作远端。
2. 配置 Apple Developer Team、正式签名、App Store Connect 条目和隐私清单。
3. 在有自有发布仓库之前继续关闭原作新闻与更新接口；之后接入 Leo 自己的版本源。
4. 增加离线崩溃日志导出按钮，不默认上传用户数据。
5. 补充 GPLv3 源码发布流程、第三方素材许可证清单和新生成素材的权属记录。

## P3：形成自己的游戏差异

建议围绕“地牢围攻”而不是只做换皮：

1. 围攻事件：每若干层出现守城/突围回合，改变传统单向下楼节奏。
2. 狮印系统：把狮首徽记变成可成长的局外天赋，但避免付费数值。
3. 中文叙事重写：重做开场、五大区域章节文本、Boss 动机和通关结局。
4. 首个 Leo 专属英雄与一套专属敌人，作为真正区分原作的最小内容包。

建议顺序：先交付一套完整高清素材，再完成 P0/P1；确认视觉基线后再进入玩法差异化，避免新玩法继续绑定旧 UI 和旧素材结构。
