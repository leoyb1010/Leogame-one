# 《Leo的地牢围攻》个人专属版完整升级总纲

> 文档性质：产品定位、视觉升级、打击感、专属玩法、Apple 适配与发布路线的唯一执行总纲
>
> 适用平台：第一阶段只覆盖 macOS、iPhone、iPad；Android 暂不改动
>
> 当前产品名：Leo的地牢围攻
>
> Apple Bundle ID：`leogameone`
>
> 默认语言：简体中文，可在设置中切换英文
>
> 当前版本基线：`1.0.0`

## 1. 最终结论

《Leo的地牢围攻》不应停留在“原作换名字、换图标”的层面。个人专属版应围绕四个核心感受建立自己的身份：

1. **一眼能认出是 Leo 的游戏**：狮首、翡翠火、古金、攻城纹章形成统一品牌语言。
2. **每一次攻击都有重量**：命中瞬间同时具备动作、停顿、闪光、粒子、声音、震动与数字反馈。
3. **真正围绕“地牢围攻”形成玩法差异**：加入围攻事件、据点、突围和狮印成长，而不是只修改文本。
4. **是一个私密、离线、长期可玩的个人版本**：无广告、无强制账号、无默认上传，存档可本地备份和导出。

推荐执行顺序是：

**视觉基线与素材管线 → 打击感垂直切片 → 全武器反馈接入 → Apple UI 精修 → 个人专属系统 → 围攻玩法与原创内容 → 发布加固。**

先做一套可以反复对比的“高清 + 强打击感”垂直切片，再批量改造全游戏。这样能尽早确定风格，避免大量素材和代码返工。

## 3. 个人专属版产品定位

### 3.1 一句话定位

**一款为 Leo 定制、中文优先、完全离线、兼具精致像素美术与强烈战斗反馈的单人地牢围攻 Roguelike。**

### 3.2 核心玩家承诺

- 买断式/个人使用体验，不插入广告，不做强制内购。
- 无需注册账号，不要求联网，不默认上传存档和日志。
- 每局仍保留 Roguelike 的随机、风险和策略深度。
- 失败可以复盘，成长来自理解系统，而不是付费数值。
- Apple 三端共享同一套视觉和玩法规范，但针对屏幕与输入方式分别适配。

### 3.3 品牌关键词

| 维度 | 关键词 | 禁止方向 |
|---|---|---|
| 身份 | 狮王、Leo、私人纹章、远征记录 | 通用奇幻 Logo、廉价金色渐变 |
| 世界 | 地下堡垒、围攻、古代王国、翡翠火 | 现代军事、科幻枪械 |
| 色彩 | 深炭黑、旧铜金、翡翠绿、暗红 | 大面积高饱和霓虹 |
| 质感 | 石刻、旧金属、皮革、羊皮纸、像素光影 | 光滑塑料、扁平网页风 |
| 战斗 | 干脆、沉重、节制、层次清楚 | 高频乱震、满屏闪白、拖慢回合 |

### 3.4 三个版本层级

1. **基础可玩版**：中文、Apple 三端、安全区、可构建、可存档。
2. **个人专属版**：高清品牌视觉、Leo 档案、狮印、离线记录、专属设置和打击感。
3. **原创内容版**：围攻事件、专属英雄、敌人、Boss、章节叙事和结局。

本总纲的目标是完成第 2 层，并为第 3 层建立可持续扩展的技术结构。

## 4. 升级设计原则

### 4.1 原生像素，而不是模糊放大

- 角色、怪物、地砖和道具保持像素画规则，采用整数倍缩放。
- 章节插画、标题背景、图标和非像素 UI 使用高清源图。
- 不对 sprite 图集直接做普通 AI 超分后上线；如需升级，必须重绘并逐帧检查轮廓、锚点和碰撞视觉。
- 所有纹理进入运行时前统一色彩空间、尺寸、alpha、压缩和体积预算。

### 4.2 打击感不等于震得更厉害

好的打击感来自“攻击预备—接触—受击—结果”的清晰节奏。屏幕震动只是其中一个通道，而且必须允许关闭。

### 4.3 表现层与战斗层隔离

- 战斗层只负责命中、伤害、格挡、暴击/奇袭、死亡等结果。
- 反馈层读取结果并播放表现，不反向改变战斗结果。
- 命中停顿只冻结/减速表现时钟，不冻结 Actor 调度，不修改回合时间。
- 所有反馈都由一个统一入口调参，避免特效散落在数十个武器类中。

### 4.4 Apple 三端一致，但不强求同一种布局

- iPhone 优先单手触控、最小触控尺寸和安全区。
- iPad 利用更宽空间展示信息，不简单等比放大手机 UI。
- Mac 支持鼠标、键盘、全屏和窗口缩放；像素内容仍保持锐利。

### 4.5 可访问性优先

- 屏幕震动、命中停顿强度、震动、闪光和伤害数字均可调或关闭。
- “减少动态效果”模式应同时降低位移、震动、闪光和粒子数量。
- 重要战斗信息不能只依赖颜色或震动表达。

## 6. 打击感系统完整设计

### 6.1 当前代码基础与缺口

现有工程已经具备可复用能力：

- `Char.attack(...)` 能拿到命中、格挡、有效伤害、目标是否死亡等核心结果。
- `KindOfWeapon` 已有武器命中音效和音高参数。
- `CharSprite` 已有攻击动画、闪白、血花和动作完成回调。
- `PixelScene.shake(...)` 已接入用户的屏幕震动强度设置。
- `IOSPlatformSupport.vibrate(...)` 已能触发 iOS 震动/触感或控制器震动。
- 资源中已有斩击、刺击、钝击、魔法、强击和格挡等基础声音。

当前缺口：这些反馈分散在攻击者、武器、技能和敌人代码中，没有统一的命中上下文、强度分级、材质层、设备策略和可调参数。

### 6.2 推荐技术结构

新增一个轻量的表现层入口，不修改伤害公式：

```text
战斗结算
  -> 生成 HitFeedbackContext
  -> CombatFeedback.play(context)
       -> 动画反馈
       -> 命中停顿
       -> 屏幕震动
       -> 粒子/闪光/伤害数字
       -> 音效分层
       -> iOS/控制器触感
```

`HitFeedbackContext` 至少包含：

- 攻击者与目标位置。
- 命中、未命中、格挡、免疫、造成伤害、击杀。
- 实际伤害、目标最大生命、伤害占比。
- 攻击类别：斩击、刺击、钝击、投射、魔法、爆炸、环境。
- 目标材质：血肉、骨骼、护甲、石质、软泥、灵体、木质。
- 强度：轻、标准、重、暴击/奇袭、终结、Boss 重击。
- 是否由英雄造成、是否发生在镜头内、是否允许震动。

建议代码落点：

- 新增 `effects/combat/CombatFeedback.java`：统一分发。
- 新增 `effects/combat/HitFeedbackContext.java`：只存一次命中结果。
- 新增 `effects/combat/HitFeedbackProfile.java`：集中保存强度参数。
- 在 `Char.attack(...)` 完成实际伤害计算后调用反馈入口。
- 在特殊技能中只传入覆盖参数，不重复实现震动和音效组合。

### 6.3 一次攻击的四段节奏

#### A. 攻击预备

- 轻武器：短促前倾，预备不超过 40–60 ms。
- 重武器：增加 70–110 ms 蓄力感，但不改变逻辑回合耗时。
- 远程：投射物离手前给出清晰的起手帧。
- 魔法：先出现能量聚集，再在命中点爆发。

#### B. 接触瞬间

- 攻击者向目标方向推进 1–2 个逻辑像素。
- 目标沿受力方向后挫 1–3 个逻辑像素，然后回到格子中心。
- 播放短命中停顿、接触闪光和瞬态音效。
- 粒子方向必须与攻击方向一致，不做无方向的圆形喷溅。

#### C. 受击恢复

- 目标闪色 1 次，不连续高频闪烁。
- 重击可有一次 95%→105%→100% 的像素安全缩放；普通攻击不需要夸张拉伸。
- 血花、碎屑或魔法粒子根据目标材质选择。
- 伤害数字在接触后立即出现，移动距离短，避免遮挡棋盘信息。

#### D. 结果确认

- 击杀：比普通命中多一层低频声音、粒子和略长停顿。
- 格挡：金属火花、硬质声、极短反向位移，不播放血花。
- 未命中：挥空声与轻微动作过冲，不震屏、不触发重震动。
- 免疫：冷色反馈和“免疫”文字，不使用命中红光。

### 6.4 命中停顿参数

命中停顿必须只影响视觉表现，不能使用线程阻塞、`sleep`，不能停止 Actor 队列。

| 事件 | 建议停顿 | 说明 |
|---|---:|---|
| 轻击命中 | 25–35 ms | 匕首、飞镖、小型怪物攻击 |
| 标准命中 | 40–55 ms | 剑、斧、普通法术 |
| 重击命中 | 65–85 ms | 锤、巨剑、蓄力攻击 |
| 暴击/奇袭 | 90–115 ms | 必须有明显但不拖沓的确认感 |
| 普通击杀 | 75–100 ms | 与死亡动画起点对齐 |
| Boss 终结 | 120–140 ms | 上限 140 ms，防止破坏节奏 |
| 格挡/招架 | 35–50 ms | 强调硬碰撞，随后立即恢复 |

约束：

- 连续攻击时采用衰减，300 ms 内第二次反馈降至 75%，第三次降至 55%。
- 多目标 AoE 只按主目标播放一次全局停顿和震屏，其他目标只播放局部反馈。
- “减少动态效果”模式下停顿减半；“关闭命中停顿”时完全跳过。

### 6.5 屏幕震动参数

| 强度 | 幅度建议 | 时长建议 | 使用场景 |
|---|---:|---:|---|
| 无 | 0 | 0 | 挥空、毒伤、持续伤害 |
| 轻 | 0.15–0.25 | 60–90 ms | 普通近战命中 |
| 中 | 0.35–0.55 | 90–130 ms | 重武器、强法术 |
| 重 | 0.7–1.0 | 130–180 ms | 暴击、精英击杀 |
| 特殊 | 1.2–1.8 | 180–260 ms | Boss 落地、场景坍塌，不用于普通攻击 |

要求：

- 优先沿攻击方向震动，再加入极小随机扰动。
- 调用现有 `SPDSettings.screenShake()` 作为全局倍率。
- 同屏多次震动要合并取最大值，不能简单叠加导致镜头失控。
- iPhone 小屏默认强度低于 Mac/iPad 约 15%。

### 6.6 武器手感矩阵

| 类别 | 动作 | 停顿 | 音效 | 粒子 | 震动 |
|---|---|---|---|---|---|
| 斩击 | 横向弧线、短推进 | 中 | 金属切入 + 血肉层 | 弧形血点/碎布 | 轻到中 |
| 刺击 | 直线突进、快速回收 | 短而尖 | 高频穿刺 + 细小冲击 | 方向集中的细粒子 | 极短轻震 |
| 钝击 | 慢起手、强后挫 | 较长 | 低频撞击 + 材质碎裂 | 石屑/骨屑/尘土 | 中到重 |
| 投射 | 出手与命中分离 | 命中时短停顿 | 飞行声 + 接触声 | 单方向火花/血点 | 仅英雄命中时轻震 |
| 魔法 | 聚能、命中扩散 | 依技能级别 | 能量瞬态 + 元素尾音 | 元素专属粒子 | 中等、持续短 |
| 格挡 | 反向弹开 | 35–50 ms | 清脆金属/硬质声 | 火花，不出血 | 单次清晰触感 |

### 6.7 目标材质矩阵

目标材质由怪物基类/属性声明，默认值为血肉，特殊敌人显式覆盖：

| 材质 | 声音主体 | 视觉主体 | 禁用反馈 |
|---|---|---|---|
| 血肉 | 湿润冲击、布料 | 暗红血点 | 过亮火花 |
| 骨骼 | 干脆骨裂 | 骨屑、灰尘 | 大量血花 |
| 护甲 | 金属撞击、摩擦 | 黄白火花 | 软质喷溅 |
| 石质 | 低频硬撞、碎石 | 石屑、粉尘 | 血色闪光 |
| 软泥 | 黏液拍击 | 对应颜色液滴 | 金属火星 |
| 灵体 | 空气撕裂、低混响 | 冷色雾粒 | 实体后挫过大 |
| 木质 | 木裂、闷响 | 木屑 | 金属回响 |

### 6.8 音效分层

每次重要命中最多由四层组成：

1. **瞬态层**：决定攻击是否“脆”，长度极短。
2. **武器层**：斩、刺、钝、箭、法术。
3. **材质层**：血肉、骨骼、金属、石头、软泥。
4. **重量尾音**：只用于重击、暴击、击杀和 Boss，不应用于每一刀。

混音规则：

- 单次命中音量总和不能削波；多层使用预留余量。
- 普通音高随机建议控制在 ±4%，不使用过大的随机范围破坏武器身份。
- 连续命中对相同音效做轻微音高轮换，避免“机关枪式重复”。
- 音效文件统一无多余静音头，接触瞬态在播放后 10 ms 内到达。
- iPhone 外放重点检查中频清晰度；低频不能只在耳机上成立。

素材命名建议：

```text
hit_slash_light_01.wav
hit_slash_heavy_01.wav
impact_flesh_01.wav
impact_armor_01.wav
impact_bone_01.wav
finisher_low_01.wav
parry_metal_01.wav
```

母带保留 WAV，运行时再按工程格式转换。每组至少 3 个近似变体。

### 6.9 iPhone/iPad 触感

| 事件 | 触感建议 | 备注 |
|---|---|---|
| 普通命中 | 轻触感 | 仅玩家主动攻击且命中 |
| 重击/暴击 | 中触感 | 不连续叠加 |
| 格挡/招架 | 清晰短触感 | 与金属声同步 |
| 玩家受重伤 | 中到重触感 | 生命危险时可加强 |
| 击杀普通敌人 | 默认不额外加强 | 避免每回合都震 |
| Boss 终结 | 单次重触感 | 作为稀有奖励反馈 |

设置项：`关闭 / 轻 / 标准 / 强`。默认“标准”，减少动态效果时自动降一级。iPad 无可用触感能力时静默跳过，不影响流程。

### 6.10 伤害数字与文字

- 普通伤害：米白或浅红，小幅上移。
- 重击：字号增加 10%–15%，不使用巨大遮屏数字。
- 暴击/奇袭：旧金色描边，并显示“暴击”或对应中文事件词。
- 护甲吸收/格挡：灰蓝色，避免与真实伤害混淆。
- 治疗、护盾和伤害必须拥有不同图形/文字特征，不能只靠颜色。
- 多段伤害在 200 ms 内可合并显示总值，但日志仍保留每段结果。

### 6.11 打击感设置页

新增“战斗反馈”设置组：

- 命中停顿：关 / 轻 / 标准。
- 屏幕震动：沿用现有强度设置。
- 触感反馈：关 / 轻 / 标准 / 强。
- 受击闪光：关 / 低 / 标准。
- 伤害数字：关 / 精简 / 完整。
- 粒子密度：低 / 标准 / 高。
- 减少动态效果：总开关，并覆盖上述高强度选项。

### 6.12 打击感垂直切片

首个切片只覆盖以下组合：

- 英雄：战士。
- 武器：短剑或长剑、匕首、战锤。
- 敌人：老鼠（血肉）、骷髅（骨骼）、装甲敌人（护甲）、软泥怪（软泥）。
- 事件：普通命中、未命中、格挡、重击、击杀、玩家受击。
- 平台：一台 Dynamic Island iPhone、一台 iPad、Apple Silicon Mac。

垂直切片验收：

- 关闭声音后，仍能仅靠动作与画面区分轻击和重击。
- 关闭画面后，仅靠声音能区分斩击、刺击、钝击和格挡。
- 三种设备上的输入到反馈没有可感知的额外延迟。
- 20 次连续攻击不会发生镜头漂移、粒子持续残留或声音削波。
- 开关所有反馈选项后，战斗伤害、随机结果和存档完全一致。

### 8.1 设备矩阵

| 类别 | 代表设备 | 方向 | 必测页面 |
|---|---|---|---|
| 小屏 iPhone | iPhone SE 尺寸 | 竖屏 | 标题、英雄选择、游戏、背包、设置 |

### 8.2 UI 规则

- 所有关键按钮在安全区内布局；背景可以延伸到屏幕边缘。
- 最小触控热区建议不低于 44×44 pt，像素图标可小于热区。
- 中文按钮不能通过缩到难以阅读来适配；优先扩宽、换行或调整布局。
- iPad 弹窗设置最大宽度，避免文字横跨整个屏幕。
- Mac 窗口缩放时重新计算布局，但地图采用整数倍缩放优先。

### 8.3 输入反馈

- 触摸按下、拖动、长按和取消要有一致视觉状态。
- 鼠标悬停只在 Mac 出现，不影响触屏布局。
- 外接键盘/控制器焦点必须可见。
- 误触高风险操作保留确认或撤销路径。

## 10. “地牢围攻”原创玩法

### 10.1 围攻事件核心循环

普通探索中，每个区域安排一次可预判的围攻节点：

1. 玩家发现据点并获得准备回合。
2. 选择修复防线、布置陷阱、寻找补给或提前突围。
3. 敌人从多个入口分波推进。
4. 玩家保护核心目标，或在限定条件下打开撤离路线。
5. 根据剩余防线、耗时和可选目标进行结算。

围攻不能把游戏变成实时塔防；仍使用原有回合制 Actor 系统。

### 10.2 首个可玩围攻章节

建议主题：**翡翠火前哨站**。

- 地图：中央狮印火盆，三条进攻路线，两处可修复障碍。
- 波次：侦察、混合兵、重甲破门者、精英队长。
- 玩家选择：守住火盆、开启侧门突围、牺牲补给换取防线。
- 奖励：知识印记、外观纹章、下一地区的一次性战术优势。
- 失败：不立即结束整局，但失去据点奖励并触发不同后续叙事。

### 10.3 首个 Leo 专属内容包

- 1 名专属英雄：围城者/狮卫方向。
- 1 套专属初始装备。
- 4 个普通敌人：侦察者、破门者、火罐兵、地穴工兵。
- 1 个精英敌人：狮印篡夺者。
- 1 个 Boss：地城攻城王。
- 1 个完整区域故事、开场和双结局。

内容包开始制作前，必须先完成打击感和 UI 组件，否则新增角色仍会绑定旧表现。

## 11. 技术改造地图

| 子系统 | 当前可复用点 | 计划改造 | 主要风险 |
|---|---|---|---|
| 战斗结算 | `Char.attack(...)` | 生成统一命中反馈上下文 | 重复触发、随机序列变化 |
| 武器音效 | `KindOfWeapon.hitSound` | 升级为武器类别 + 材质分层 | 音量削波、特殊武器覆盖 |
| 角色动画 | `CharSprite` | 推进、后挫、闪色、局部停顿 | 回调时序、sprite 锚点 |
| 屏幕震动 | `PixelScene.shake` | 方向、强度分级、合并与衰减 | 镜头漂移、晕动不适 |
| iOS 触感 | `IOSPlatformSupport.vibrate` | 事件强度映射与设置项 | 设备能力差异 |
| 设置 | `SPDSettings` / `WndSettings` | 战斗反馈与减少动态效果 | 老设置迁移 |
| 安全区 | `getSafeInsets` | 建立页面级截图回归 | 旋转与窗口变化 |
| 素材 | 现有 assets 管线 | HD 插画、9-slice、战斗 FX | 体积、授权、色彩空间 |
| 存档 | 现有 Bundle 存储 | 远征档案、快照导入导出 | 版本兼容、覆盖风险 |
| 围攻 | Actor/Level 系统 | 波次、据点、结算对象 | 关卡软锁、性能峰值 |

### 11.1 明确禁止的实现

- 不在主线程中使用 `sleep` 制造命中停顿。
- 不让表现层调用随机数影响战斗 RNG；视觉随机使用独立随机源。
- 不在每个武器类复制同一套屏幕震动和震动代码。
- 不用全屏闪白作为所有重击的默认反馈。
- 不直接覆盖用户存档，不在导入失败时删除原文件。
- 不为了个人功能引入账号、遥测或常驻网络服务。

## 14. 质量与性能验收

### 14.1 功能回归

- 新建、存储、读取、死亡、重开、通关流程正常。
- 中英文切换后所有新增 UI 都能立即正确显示。
- 固定种子与固定操作序列的战斗结果不因反馈设置变化。
- 无网络时启动、游玩、存档、导出日志均正常。
- Android 未被本轮共享代码意外破坏；如共享 core 必须至少执行编译检查，但不进行 Android 产品改造。

### 14.2 性能预算

- 目标设备正常战斗维持稳定帧率，反馈峰值不造成肉眼卡顿。
- 一次普通攻击的新增短生命周期对象应可控，优先复用 emitter/对象池。
- AoE 同屏 10 个目标时，全局震动和停顿只触发一次。
- 粒子密度“低”适用于旧设备，“标准”为默认，“高”只增加表现不改变信息。
- 音效并发设置上限，避免 Boss 战大量重复声音。

### 14.3 视觉回归

- 标题、游戏 HUD、背包、设置、日志、Boss 战各保留中英文截图。
- iPhone 横竖屏四角、Dynamic Island 和 Home Indicator 无关键遮挡。
- iPad 弹窗不过宽，Mac 缩放不糊。
- 减少动态效果开启后，所有强闪光、强震动和大位移均被降低。

### 14.4 打击感盲测

建议邀请 3–5 名体验者，在不知道配置的情况下完成：

- 判断三种武器中哪一种最重。
- 判断目标是血肉、骨骼还是护甲。
- 判断普通命中、格挡和重击。
- 评价连续 20 次攻击是否疲劳、晕动或过吵。

通过标准：大多数人能正确识别事件，同时没有人认为普通战斗“每一下都过度震动”。

## 15. 存档与兼容策略

- 新字段必须提供缺省值，旧存档没有个人档案时自动初始化。
- 表现层配置独立保存，不写入单局战斗状态。
- 围攻事件新增存档字段时包含事件版本号和阶段状态。
- 每次结构迁移前自动生成一次可恢复快照。
- 任何迁移失败都返回原存档并显示中文错误，不尝试半完成状态继续游戏。
- 不修改现有战斗随机数顺序来生成视觉粒子；粒子使用独立随机源。

## 16. 开源、版权与发布边界

- 继续保留原项目 GPLv3 许可和原作者版权声明。
- 对外分发二进制时同步提供对应版本源码及构建说明。
- Leo 新增代码仍需按 GPLv3 的分发要求处理。
- 原作代码许可证不自动授予第三方字体、音乐、音效和生成素材的权利。
- 每份新增素材记录来源、作者/生成工具、日期、Prompt、后期修改与允许用途。
- 未确认权属的音效、字体和图片不能进入发布构建。
- 新建 Leo 自有 GitHub 远端后，保留 `upstream` 只拉取原作更新，避免将个人发布错误推回原仓库。

## 17. 完成定义（Definition of Done）

个人专属版达到“完成”必须同时满足：

1. Apple 三端构建和安装成功。
2. 中文首次启动，英文可完整切换，无新增缺失键。
3. 所有核心页面通过安全区和清晰度检查。
4. 斩、刺、钝、投射、魔法、格挡拥有可区分的反馈。
5. 命中停顿、震屏、闪光、粒子、触感均可调整或关闭。
6. 打击感开关不改变伤害、回合、RNG 和存档。
7. Leo 远征档案、狮印和存档保险箱完全离线工作。
8. 至少一个围攻事件从准备、战斗到结算完整可玩。
9. 固定种子通关回归通过，无软锁和存档损坏。
10. 源码、构建说明、许可证和素材权属可以对应到发布包。

## 20. 最终产品愿景

完成后的《Leo的地牢围攻》应该在第一眼、第一刀和第一局结束时分别给玩家三个明确答案：

- **第一眼**：这不是原作的简单换皮，而是 Leo 的专属地牢世界。
- **第一刀**：武器有重量、敌人有材质、命中有结果，且反馈克制、不吵闹。
- **第一局结束**：离线也能留下属于自己的远征历史，并愿意继续挑战下一次围攻。

这三点同时成立，个人专属版才算真正建立完成。
